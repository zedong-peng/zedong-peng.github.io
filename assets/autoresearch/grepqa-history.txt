# GrepQA Development Log

## Final Method

`grepqa.py` (formerly `grepqa_v21`) is the final retained method. F1 = **51.69** on LoCoMo-10.

Design:
- 3 question-side predicates (different keyword angles, no answer guessing)
- Symbolic exact-match retrieval with `must/should` scoring and speaker filter
- `top_k=8`, `window=2`
- Date-aware answer prompt that resolves relative time expressions from session timestamps

add v33: enumeration-aware predicate generation (failed pilot -2.58pp)

v33 attempted to fix Cat1 multi-answer (169 questions, avg F1=0.33) by:
- LLM classification of enumeration vs single-answer questions
- Diverse predicates targeting different semantic clusters for enum questions
- 'List ALL instances' instruction in answer prompt

Result: pilot F1=0.4699 (-2.58pp vs v21 pilot 0.4957)

Root cause: diverse predicates target assumed ANSWER keywords, not question
keywords — same failure mode as v20 (answer-side guessing) and v27.
Cat1 multi-answer is a structural limitation of keyword-based retrieval:
cannot generate question-side predicates diverse enough to cover all instances
across sessions without knowing the answer in advance.

grepqa_v34.py module documentation at c809021ea8fd1132e36b694ad4fefd94c3726df6

GrepQA v34: v21 predicates + question-type-aware answer generation.

Root cause insight from comparing full-run versions:
  v11 Cat4=0.6039 (best ever) vs v21 Cat4=0.5822 (+2.17pp deficit).
  v11 answer prompt: "list ALL values mentioned in the context, comma-separated"
  + max_tokens=128 (v21 uses 64).
  104 of v11's 140 Cat4 wins vs v21 are answer-quality improvements
  (v21 retrieved the right context but paraphrased/truncated the answer):
    Ref: "gaining strength" → v11: "Gaining strength." vs v21: "He's been working on it for two years."
    Ref: "finding inner peace" → v11: "Inner peace." vs v21: "Incorporating relaxation, self-care..."
    Ref: "big family reunion" → v11: "A big family reunion." vs v21: "Family reunion" (partial)

  But v11 Cat2=0.4469 (-9.60pp vs v21's 0.5429) because "list ALL values" causes
  temporal questions to produce a list of dates/times instead of one precise answer.

v34 fix: CONDITIONAL ANSWER ROUTING based on question type.
  - Temporal question (When/How long/How often/Since when/...):
    → v13-style prompt: "Be concise, resolve relative dates, shortest form possible"
    → max_tokens=64
  - Non-temporal question (What/Why/How does/Who/Where/...):
    → v11-style prompt: "List ALL values, be complete, comma-separated if multiple"
    → max_tokens=128

Detection heuristic (deterministic, no LLM call):
  84% recall on Cat2 (269/321), 6.3% FPR on Cat4 (53/841).
  No extra API call — the routing is pure Python regex.

Everything else identical to v21 (predicates, execute, top_k=8, window=2).

Key principle: predicates remain question-side (v21's proven design).
Only the ANSWER generation changes, and only conditionally.
